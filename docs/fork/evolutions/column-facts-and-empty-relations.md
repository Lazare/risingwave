## Summary

Derive, per plan node, which columns hold a constant and which are never `NULL`, simplify
predicates and projections with these facts, and replace the sub-plans whose predicates can never
be true with an empty relation, then propagate the emptiness upwards. In streaming the removed
sub-plans never get fragments, backfills or state.

## Motivation

Layered views often contain branches that are dead for a given consumer: a `UNION ALL` branch with
a constant discriminator filtered away above, `x IS NULL AND x = 1` after view inlining, a left join
whose optional side is filtered to nothing. The batch optimizer already folds some of these; the
streaming optimizer did not, and a streaming job pays for every dead branch with backfills, join
and aggregation state and actors, for its whole life.

## What it does

Rules (in this order, one bottom-up stage after the final predicate pushdown):

1. `ColumnFactsSimplifyRule` (constants, never-`NULL` columns including `NOT NULL` table
   constraints, redundant conjuncts, `CASE` with constant conditions);
2. `NeverTruePredicateRule` (constant `FALSE`/`NULL`, `x IS NULL` with a null-rejecting conjunct,
   contradictory comparisons with constants);
3. `EmptyRelationPropagateRule` (empty inputs of joins, unions, `LIMIT 0`);
4. `EmptyInputSimplifyRule` (an aggregation without `GROUP BY` over an empty input becomes its
   constant row);
5. `ConstantRowJoinRule` (an inner join with one row of constants becomes a filter and a
   projection);
6. aggregate of a constant: `min`, `max`, `first_value`, `last_value` of a constant are that
   constant.

```sql
CREATE TABLE f (id int PRIMARY KEY, kind varchar, amt int);
CREATE TABLE d (id int PRIMARY KEY, name varchar);
CREATE VIEW v AS
  SELECT id, 'a' AS src, amt FROM f WHERE kind = 'a'
  UNION ALL
  SELECT f.id, 'b' AS src, f.amt FROM f JOIN d ON f.id = d.id WHERE f.kind = 'b';
CREATE MATERIALIZED VIEW mv AS SELECT * FROM v WHERE src = 'a';
-- without: Union(Scan(f) + Filter, HashJoin(Scan(f), Scan(d)) + Filter(false))
-- with:    Filter(kind = 'a') <- Scan(f); the join, the scan of d and its backfill are gone
```

When a materialized view is created with one of the streaming plan-reduction variables, the
frontend plans it a second time without them and reports to the user (notice) and in the log the
fragments, operators and table scans saved.

## Configuration

`streaming_prune_empty_relation` for new streaming jobs, `batch_simplify_column_facts` for batch
queries; both default false, settable with `SET`, `ALTER SYSTEM SET` or `[session_init]`. Existing
streaming jobs are not re-planned.

## Correctness / safety argument

A streaming plan is frozen at creation, so a fact must hold for all future rows, under
retractions and three-valued logic. Facts are properties of the rows a filter or scan can output.
`NOT NULL` constraints are used because a table drops the rows that violate them whatever writes
them; not for tables with generated columns or columns added with an unknown or `NULL` default.
Parts of the plan that may carry a watermark (`now()`, watermark columns, temporal joins) are never
replaced with an empty relation, so `EMIT ON WINDOW CLOSE` jobs still plan. In batch, the rules
never claim that an expression that may fail is not `NULL`.

## Limits and risks

- Contradictions only for booleans, integers, varchar, date, time and timestamps compared directly
  with a constant of the same type; types are not assumed discrete.
- If `ALTER TABLE ... DROP NOT NULL` becomes supported, plans relying on `NOT NULL` facts must be
  invalidated (open point of the design note).
- With selective barriers, an empty `VALUES` at the root of a fragment is classified "always
  awake" (open point, not checked on a build with both).

## Upstream relation

Upstream batch has `EmptyRelationPropagateRule`-style folding for a few shapes (the contradictory
`NULL` filter fold of the batch planner is a fork correction, see `../corrections/`). Comparable
rules exist in other planners (constant folding and empty-relation pruning in Calcite,
CockroachDB). Upstream PR candidate once stabilized; not proposed yet.
